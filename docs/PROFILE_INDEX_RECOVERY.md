# 配置列表备份与故障恢复

0.3.8 / Build 11 为配置列表增加本机元数据备份。导入、删除、收藏、分组、备注和默认策略成功保存后，尝试更新 `profiles.backup.json`；既有健康索引首次读取时补建缺失备份。设置与维护 → 配置列表备份可查看时间、数量和与当前列表的一致性，也可明确更新备份；尚未导入配置的新存储可手动建立空列表备份。

## 恢复流程

- 索引 JSON 损坏或在已有备份时缺失，主窗口持续提示并清空无法核验的列表，不将损坏索引当作空列表覆盖。规则加载和助手会话检查继续工作。
- “查看恢复”先展示备份中的名称、分组、收藏和默认策略。必须断开 VPN、没有活动配置且其它写入结束后才能确认。恢复期间禁止连接、导入、维护和退出。
- 确认同时绑定故障索引与备份的 SHA-256（包括索引缺失），两者变化后必须重新检查。健康主索引不允许用备份回退。
- 校验整个备份的版本、唯一 ID、规范相对路径，以及每个引用配置的可读性；任何缺失或不安全配置都拒绝整个恢复，不静默漏项。配置正文和历史版本保留原位，Keychain 不变。
- 可读取的故障索引先以 `profiles-damaged-UUID.json` 私有原子保存，再原子发布恢复列表。缺失索引无需归档。恢复不删除备份。

## 写入与边界

主索引、备份和故障归档均使用 0600 私有原子写入。读取限制为普通文件、拒绝叶节点链接/FIFO/设备，索引和备份各不超过 16 MB；每个配置文件仍限 2 MB。备份不含配置正文、证书或 Keychain 密码，但含用户录入的名称和备注，应按私有数据保管。

主索引发布是保存的提交点。随后备份写入失败不会把已提交的导入报为失败或删除其配置文件；界面分别报告无可用备份或备份不一致。损坏的普通备份可从健康主索引明确重建；链接或特殊文件需用户检查其存储位置，应用不会跟随或覆盖。

这是本机元数据故障恢复，不能替代异机备份；磁盘损坏、配置正文丢失、超限/不可读取的故障索引以及多个外部进程同时修改目录，仍可能需要保留现场后人工处理。无完整可用备份时不猜测元数据，也不自动重置或删除存储。

## 验证

新增核心测试覆盖完整元数据和历史保留、缺失索引、两类过期确认、健康索引拒绝回退、重复 ID/路径穿越、配置缺失、运行时 FIFO、索引/备份链接/FIFO/超限、备份失败后的导入提交、旧存储迁移、删除不复活、未知备份版本及首次空列表备份。原生 AppModel 自检验证恢复预览、连接中拒绝、写入时退出阻止、过期确认失效和备份重建；工作流捕获实际 SwiftUI 恢复窗口。完整检查以本轮 PR 的 Actions 为准；真实磁盘故障和用户操作仍需 Mac 验收。
