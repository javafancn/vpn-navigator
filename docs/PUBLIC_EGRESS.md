# 公网出口检测

0.7.0（Build 18）。网络诊断右上角「公网出口…」。打开窗口不会请求公网；选择 IPv4／IPv6 后点击开始，才向固定 HTTPS 检测服务发送 GET 请求。检测不连接／断开 VPN、不修改 DNS、路由或防火墙。

## 请求范围与隐私

- IPv4：`https://api.ipify.org/`；IPv6：`https://api6.ipify.org/`。按 ipify 官方说明，后一端点仅提供 IPv6 请求；不可达可能与地址族、网络阻断或服务状态有关，不直接判定 VPN 失败或泄漏。
- 服务方能看到该请求的出口 IP；界面在开始前说明。请求不携带配置、凭据、证书、原始日志或自定义查询标识。只允许固定端点，不跟随 HTTP 跳转。
- 每请求使用独立临时 URLSession，关闭共享 Cookie、凭据、缓存并发送禁止缓存的请求头；不提供 HTTP 认证或客户端身份，HTTPS 服务端信任由系统正常验证，不绕过证书检查。
- 请求尝试停用系统 HTTP／HTTPS／PAC／SOCKS 代理，保留系统路由（包括 utun）。若系统元数据仍报告代理／缓存，或缺少连接元数据，则不声称核验 VPN 路径。其他 TUN 软件或网络扩展仍可影响请求。
- 响应只接受有界 ASCII 单地址文本，最多 128 字节；拒绝 JSON／HTML、多个地址、错误地址族、私有／特殊地址和文档地址。IPv6 使用保守的全球单播范围；不支持的范围不会被当作有效出口。每 HTTP 请求硬期限 8 秒，含助手与路由查询的整体期限 25 秒。

## 地址查询与路径核验

显示检测服务返回的公网地址，以及该 HTTPS 请求的耗时。它不是带宽测试、ICMP 延迟或完整连接质量结论。

请求的实际远端 IP 来自 URLSession 连接元数据，而非将回显的客户端出口地址当作检测目标。具备可用元数据、当前会话已核验且未使用代理／缓存时，绑定配置 UUID、连接尝试、路由模式和版本，通过既有只读助手 API 查询该远端 IP 的系统接口与策略。原始配置模式只展示系统观测；受管模式区分 VPN 路由匹配、按规则直连、路径不一致及无法核验。

开始、逐项完成、路由查询后和最终完成均核对会话。地址族传输元数据不匹配、助手未知、证据不完整或只取得地址时，显示无法核验，不把有响应当作 VPN 生效。IPv4 和 IPv6 独立完成，保留部分成功／失败结果；单族检测失败不等同于该地址族在所有目标均不可用。

检测期间连接、路由版本、助手核验／保护状态或已观察到的物理网络标识变化时，取消并清除旧结果；取消、重启检测、关闭窗口或过期任务不能回写当前结果。关闭窗口清空地址结果，不写入连接历史、诊断日志、支持报告、加密备份或偏好设置。

路由表是过程采样，服务方回显也不是独立证明。这不是物理抓包，不验证 DNS 解析器的公网出口、不检查全部目标或所有流量，也不提供无泄漏保证。现有系统 DNS 解析和一键排障入口继续独立提供。

## 自动化与人工边界

核心用例验证文本／地址族／公网边界、端点限制、会话变化、缺失元数据、代理／缓存、实际检测目标绑定、VPN／直连／原始配置及不匹配判断。原生自检使用数值回环 IPv4／IPv6 HTTP 服务验证流式大小、响应状态、认证拒绝、跳转不跟随、取消和硬超时；注入式模型检查手动触发、部分结果、整体期限、过期会话和 VPN 状态保持。测试不联系 ipify，不请求 VPN 或系统权限。

生产 HTTPS 服务可达性、真实 VPN 下的地址回显、代理／TUN 共存、Wi-Fi／有线切换和物理流量抓包仍需用户 Mac 验收。既有发布签名、公证及网络安全门槛保持。
