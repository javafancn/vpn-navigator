# 后台服务偏好与维护恢复（0.3.3 / Build 6）

“连接偏好”现在提供每天自动更新国内 IPv4 规则、登录时启动两个开关，并显示各自实际服务状态。开关保存用户期望，状态显示 launchd / 系统授权结果；失败时保留期望并显示原因，可以打开系统授权后“按偏好重试”。关闭自动更新不影响手动下载或导入规则。登录启动不会自动连接 VPN。

首次迁移默认开启规则更新，登录启动沿用当前已启用的登录服务。之后明确关闭的选择不会因升级、代码哈希变化或已有已加载服务而被覆盖。旧版维护已经移除、且从未保存的登录选择无法追溯；迁移后可重新开启。

升级、修复和卸载准备只临时停止实际服务，不改写偏好。安装完成、助手启用后，重新打开应用会按偏好恢复两个服务，同版本修复也适用。已正常运行的服务不会重复写 plist 或重新启动。维护停用助手后，应用不会自动重新注册 root 服务；仍需用户通过可信安装包或正式系统授权完成安装。

启用用户服务前必须通过现有双向身份验证的助手健康检查；Local 通道继续校验管理员批准、当前应用身份及完整 payload，安装事务未提交时不能启用。此功能不会绕过损坏安装、未完成事务或网络恢复证据。服务操作期间阻止并发维护、修复退出和重复切换。

## 验证

- 核心用例验证首次默认值、已有登录迁移、关闭选择持久化及服务临时移除后的期望保留。
- 原有 Local 服务自检在一次性 GitHub macOS runner 上调用真实 AppModel 和用户 launchd，验证已加载服务不会覆盖关闭选择、同版本恢复两个服务、重复恢复不重写规则 plist，以及实际维护停用后偏好仍在。使用随机独立 UserDefaults suite，结束时删除测试偏好。
- 安装、真实隔离 TLS/MFA、升级、三个中断阶段、XPC 身份和卸载工作流继续执行。结果以 PR 对应 Actions 为准。

用户实际点击、系统登录与重启、管理员授权取消和长时间后台运行仍需真机记录；此功能不表示完成产品发布门槛。
