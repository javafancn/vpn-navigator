# 规则、下载、备份和连接诊断改进

本次改动基于 0.8.13 源码工作区，包含此前性能修复；不代表已经替换本机安装的应用。

## 双栈规则更新

- IPv6 下载候选与提交使用相同的数量及差异校验，异常候选不会先改变 IPv4 缓存。
- IPv4/IPv6 缓存统一存入 `Rules/routing-rules.json`，通过一次原子重命名发布。首次使用兼容旧的两个文本缓存。
- 应用和后台规则任务通过文件锁互斥写入。候选文件在调用助手前完成校验与写盘。
- 助手拒绝时保留完整旧缓存；助手已应用但缓存发布失败时，尝试恢复旧的活动规则。恢复未确认会明确提示断开并重连。
- 更新失败的暂存文件、额外历史快照会清理；中断进程遗留的暂存文件在下一次写入时回收。中途退出时缓存仍是完整旧版或新版，活动会话以助手报告为准。
- 连接和切换至规则模式前重读同一份完整缓存。自测使用独立的临时缓存。

## 有界下载

- IPv6 规则下载最多 7,999,999 字节，总时限 30 秒。
- 安装包最多 400,000,000 字节，总时限 300 秒；直接流式写入私有临时文件，不在内存拼装安装包。
- 响应头声明超限时立即拒绝；无 Content-Length、分块及解压后的响应也按实际收到的字节检查。
- 限制 HTTPS 来源和重定向域名；拒绝非 200、空响应。超限、取消、超时和写入失败均清理临时文件。
- 安装包的签名、Team ID 与 Gatekeeper 检查继续执行。

## 选择性备份与容量预算

- 可以选择部分配置，选择全部历史、最近 N 个历史版本或仅当前版本。
- N 的范围为每配置 1–1000。默认仍包含全部配置及全部历史；不改变原库内容。
- 每次读取源文件、运行文件或历史文件前，按剩余预算限制读取；不再先装载完整历史后检查总大小。
- 保留最多 1000 个配置、每配置 1000 个历史、总共 10000 个历史和 16 MB 加密文件的限制。超限可以缩小选择或减少历史。
- 所选配置已被删除时拒绝导出；源文件 BOM、加密格式和恢复兼容性保留。

## 连接阶段耗时

- 网络诊断的“连接阶段耗时…”入口显示准备、启动、协商、DNS、路由规划/应用、核验、解析器生效及总耗时。
- 同样的结构化数据进入连接历史和诊断文本导出，不包含地址、域名或凭据。
- 旧版助手和旧历史没有计时字段时仍可读取；非法、重复或超出范围的计时不会进入展示和历史。
