# 审查回归修复（2026-11-03，工作区）

本轮对应审查中的 1A、1B、3、4、5、6。保留此前工作区修改，未替换已安装程序。

## 物理 DNS 的选择与校验

`SplitDNSPolicy` 现在同时校验解析器的地址族、单播有效性及归属。仅采用当前物理 LAN 内的地址、RFC1918/ULA 私有地址、当前国内规则包含且可通过自定义网段校验的公网地址，或固定的国内 DNS 候选。VPN DNS 和服务器端点始终排除。

- 手工设置 `8.8.8.8`、`1.1.1.1`、`9.9.9.9`、海外 IPv6 DNS 不会新增物理主机路由或 PF 例外，改用国内候选。
- `100.100.2.136`、`198.18.0.2` 等特殊地址在物理 LAN 外不作为 DNS 例外，避免在 PF 构造阶段失败。若确实处于观测到的 on-link LAN 内，则保留正常 LAN 路径，不添加网关主机路由，也不放宽自定义业务网段的禁止列表。
- `DualStackRoutePlan.build` 独立执行同一归属检查，不能绕过选择器直接构造海外/保留地址例外。
- 切换到国内直连时根据目标国家规则重新选择解析器；DNS 代理读取新计划的 `physicalDNS`，避免沿用旧模式的候选。

本策略不会把未收录的海外域名发送至物理 DNS。用户提供的国内 IP 规则仍是国家归属的依据。

## 空闲助手生命周期

普通 `sessionReport` 不再立即关闭 XPC；传输层也不再在三十秒无请求后关闭连接。App 打开或后台运行时保留当前身份要求下的连接，使 Helper 的客户端计数保持有效，避免每次轮询启动 root 进程及五秒退出边界竞态。

显式退出/维护保留原有关闭步骤；连接身份变化、XPC 中断和进程崩溃仍会失效连接。没有重发可能已执行的连接/路由写请求，也没有取消 Helper 的安全退出与恢复检查。

## 首次双栈连接

新增 `Resources/Rules/china-ipv6.txt`：从 APNIC 官方 2026-11-03 快照提取 2,046 条 CN IPv6 allocated/assigned 前缀。完整源文件为 4,352,423 字节、89,637 条记录，并核对官方 MD5；源文件及种子的 SHA-256 和使用条件记录在 `LICENSES/APNIC_STATS_NOTICE.txt`。

首次加载和国内直连前均补齐缺失的 IPv4/IPv6 种子。两族在同一规则缓存事务中发布；锁内重新检查是否已有规则，因此不会用旧种子覆盖并发更新。短暂锁竞争有有界重试；启动补齐失败仍尝试读取已有缓存。非法种子不会只发布其中一个地址族。数据随应用打包，首次使用无需等待后台网络下载；已有规则保持原样。

## 智能连接与唤醒

三个自动连接许可边界均改为 `await` 新的物理网络快照。许可检查更新观测结果时不调用事件调度，避免自身触发 `networkRestored` 并取消当前 generation。过时的路径读取最多重试三次；手动取消、设置变化和停止仍使结果失效。

唤醒任务在 Wi-Fi 暂时离线时保留，最多等待三十秒。恢复网络不替换正在等待的 wake 触发，因此仅开启唤醒自动连接也能在网络稍后恢复时连接。任务结束清理 pending trigger；手动断开/暂停/休眠仍立即取消，不留下延迟连接意图。

## 配置兼容

- `server-poll-timeout` 仅接受单个 `1...3600` 的整数。
- `socket-flags` 仅接受精确的 `TCP_NODELAY`。
- 保留原文、显式服务器响应等待及 TCP/UDP，不开放其它 socket flags、脚本或环境指令。
