# VPN Navigator 原生 UI 还原规范（2026-10-16）

## 基准与边界

本轮以用户上传的《VPN Navigator 网页端设计系统展示(2).png》为唯一视觉基准，代码继续基于 PR #11 的 `feat/glass-ui-fidelity-oct16`，不使用 main 的初始界面作为实现基准。

参考图是一张 1743 × 902 拼版。总览、配置和底排三个窗口的缩放比例不同。因此采用用户明确要求的统一 1100 × 700 默认窗口和 11:7 内容比例，统一侧栏与组件尺寸；底排页面适配统一窗口，不重复之前切换页面修改窗口大小的做法。

## 共享视觉规范

| 项目 | 本轮规范 |

## 逐页差距与修改

### 连接总览

旧版的标题/字段过小，快捷连接区被身份验证折叠行挤占，会话卡多了参考图没有的标题，卡片阴影过重。

本轮将电源主卡和右侧堆栈统一为330pt，电源球220pt，右下会话卡80pt；底部为两张195pt统计卡和自适应保护卡，高度统一146pt。输入框统一为表单字段。身份验证保留在快捷连接区的钥匙按钮弹出面板中，不再改变主卡布局。

### 配置文件

旧版列表偏宽，图标与行高不足，备注只有单行，文件名缺乏控件容器，标签与底部按钮不统一。

本轮列表235pt，40pt图标和更清晰的双行信息；右侧检查器使用品牌图标、四个等宽标签、名称/类别/文件/备注四行；文件名使用独立浅蓝字段，备注为两行；保存和导出使用同一按钮体系。元数据、版本历史、配置编辑和导出仍连接既有真实模型。

### 路由与规则

旧版错误地把路由模式和IPv4内容合并为一张横向大卡，IPv6预览单独浮在卡片外。

本轮恢复左侧路由模式卡、右侧IPv4卡和右下IPv6预览卡。三种模式为独立单选行，选中时使用浅蓝背景；规则信息与更新/历史操作对齐。路由左右列宽按44:56分配，组合固定380pt高度，避免为了填满窗口而把卡片中间拉出大片留白。

### 网络诊断

旧版的标题、标签、表单和检查结果密度各不相同，路由路径堆叠松散。

本轮顶部四标签使用统一36–40pt分段容器；左侧为检查结果和底部反馈，目标输入与重新检查放在标题旁的更多按钮弹出面板中，右侧为节点路径及IPv6预览；左右列宽按61:39分配。检查行42pt，节点44pt，标题与图标统一。保留真实本机诊断结果，不将路由表读取成功描述为互联网可达或VPN安全验证成功。

### 设置与维护

旧版112pt白色厚卡与参考图的紧凑操作列表不符。

本轮使用92pt横向卡，左侧46pt淡蓝图标、中部双行信息、右侧状态或操作，保持四行和统一字体。除总览外，页面标题直接对齐公共窗口顶部，不复用总览的大型品牌标题留白。服务注册、应用更新、网络恢复和关于信息沿用原逻辑。

### 菜单栏

删除额外副标题和重复统计分区，恢复品牌/开关、状态/会话、打开主窗口/退出的结构。退出时先断开当前连接，再检查状态退出，不增加虚假的国家/城市/实时速率。

## 验证与交付要求

1. 通过 macOS Swift 核心测试和 Apple Silicon/Intel 双架构应用构建。
2. 应用包通过 ad-hoc 签名验证和ZIP完整性验证。
3. 五页分别生成原生窗口截图，记录实际窗口边界。截图步骤不再 best-effort 忽略失败。
4. 逐页检查文字截断、控件重叠、底部操作可见、侧栏宽度和卡片层次。
5. 交付截图、测试应用和与原始参考图并排的对比图。只有实际截图才可称为运行效果。

## 已知外观边界

桌面壁纸、系统材质和“降低透明度”会改变背板的最终颜色。原图含不同缩放窗口以及示例连接数据；实际程序使用统一窗口和真实数据。不能据此声称像素完全一致。测试构建不含 OpenVPN 引擎，不用于连接功能验收。
