# 助手崩溃、错误反馈及升级验收

0.3.0 / Build 3 增加以下可独立复验的行为。检查结果以本 PR 和工作流日志为准。

## 控制器消失时结束引擎

助手在启动引擎前创建 root 私有 Unix 监听端点，文件权限 0600，父目录 0700；只接受 UID 0 对端。监听和连接描述符均设置 close-on-exec，避免其他子进程继承并延长控制连接的生命。

OpenVPN 使用 management-client 连接该端点。控制连接断开后由引擎自行生成 SIGTERM 并退出；没有根据旧进程数字 PID 发送信号。助手重启仍保留原始会话/恢复证据，只有明确核验原 PID 不存在后，现有“安全网络恢复”接口才恢复 DNS、路由及本应用 PF 所有权。

如果旧 PID 仍存在、被复用或无法确认，继续保留证据，不强行恢复。文件身份损坏也不自动批准未知文件。

## 保留失败原因

管理连接 EOF 可能先于进程退出回调到达。原先这条路径清理后只显示“已断开”；现在保留“意外退出”的可见失败状态和诊断事件，明确断开或重试后再改变状态。恢复不完整的具体错误不会被通用退出提示覆盖。

## 自动验收

真实回环 TLS 用例在正常连接时通过 launchctl 对固定 daemon job 注入 SIGKILL。验证其引擎退出、证据仍在、已安装助手可通过现有 typed recovery 恢复，随后再次连接/断开并拒绝错误 CA。此用例仍仅覆盖 Original 与合成网络；不替代物理分流/PF/睡眠或真实外部 MFA 验收。

安装矩阵另外构造一个使用当前代码、较低版本元数据的 0.2.0 PKG，实际安装、维护停用，再升级至 0.3.0；核验应用与批准版本/Build 一致，且旧应用身份被拒绝。这证明 Installer 的版本替换和身份切换，不能当作所有历史版本二进制的兼容证明。该合成旧包不会上传为候选产物。

参考：[OpenVPN 2.7.8 官方 management-client 文档](https://github.com/OpenVPN/openvpn/blob/v2.7.8/doc/man-sections/management-options.rst)。
