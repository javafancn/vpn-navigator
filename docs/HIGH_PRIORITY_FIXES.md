# 服务端身份与配置库并发修复

## 服务端身份校验

连接入口使用 `ProfileSafety.validateForConnection`：先执行原有的指令、路径和容量校验，再要求以下至少一项：

- `remote-cert-tls server`；
- `verify-x509-name` 的精确 `name` 或 `subject` 约束（省略类型时为精确 subject）。

仅有 CA、注释或内联材料中的同名文本、单独的 `name-prefix` 均不满足要求。显式客户端角色、冲突角色及错误参数拒绝连接；重复名称约束按最后一项判断，避免早先的精确约束掩盖后续宽泛前缀。

应用在读取保存的凭据和调用助手之前检查，特权助手在启动引擎和修改网络前独立检查。健康检查通过 `server-identity` 错误提示缺失或错误的约束。

已有配置仍可导入、编辑、导出和备份，以便保留原始文件并修复；缺少约束时不能连接。应用不猜测服务器名称或静默补入选项，需由管理员提供与实际服务端证书相匹配的配置。

## 配置库事务互斥

原复现场景为两个独立 `ProfileStore` 实例并发导入：41 次操作报告成功，但索引只保留 21 条，磁盘存在 41 份配置文件。

修复后，每个配置库通过固定的 `profiles.lock` 文件执行 `flock` 互斥，覆盖整个读取、修改、发布与恢复过程，而非仅锁定最终索引写入。

- 同一 actor 的同步嵌套调用复用外层事务，避免读取、版本保存、备份恢复互相死锁。
- 其他实例的读取也必须等待，避免把正在写入的恢复记录当作崩溃残留进行回滚。
- 等待支持取消，15 秒后明确报告繁忙；持锁进程退出由内核释放锁。
- 锁文件保持稳定、不删除，使用 `O_NOFOLLOW` 和描述符校验拒绝链接、特殊文件、不匹配的所有者及替换的 inode。配置库目录与锁文件使用 0700/0600 权限。
- 不同配置库使用各自的锁。

## 验证

独立回归入口（不依赖 XCTest）：

```sh
python3 scripts/test-profile-safety.py /path/to/swift-build-products
```

先构建 `VPNNavigatorHelper`，再传入构建产物目录。脚本兼容聚合的 `VPNNavigatorCore.o` 与传统 SwiftPM 的逐文件对象/Modules 布局。

已在本机通过：

- 服务端角色、精确名称、空白/引号解析、伪造注释/内联内容、错误角色、重复选项、宽泛前缀及非法参数。
- 真实 X.509 测试证书在有效期内、缺少身份约束时报告错误，完整配置保持健康。
- 两个 actor 实例：41 次成功导入、41 条索引。
- 再加入四个独立进程：累计 81 次成功导入、81 条索引、81 份源文件，备份索引一致。
- 版本保存、嵌套备份/恢复、锁等待取消、持锁进程直接退出后的锁释放，以及拒绝符号链接和硬链接。
- 此前的导入容量/空白处理、选择性备份与加密往返、规则事务、下载限制及连接历史回归继续通过。

新增 XCTest 还覆盖暂停更新事务时另一实例读取不能触发回滚；CI 已加入独立进程回归入口。

核心和助手编译已通过；本机仍缺完整 Xcode 的 SwiftUI 宏插件及 XCTest，完整应用、XCTest 和真实 TLS/路由会话验收需在完整 Xcode/隔离环境完成。上述校验测试不等同于已执行真实中间人攻击测试，也未替换本机已安装应用。
