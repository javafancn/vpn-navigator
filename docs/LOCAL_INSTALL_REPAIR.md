# 安装事务与中断修复（0.3.2 / Build 5）

本地安装现在以 `install-state.json` 作为受保护的安装屏障。它在旧服务停止、活动进程及网络恢复证据检查通过之后、PKG 解包之前写入。只记录 schema、版本、原生架构与阶段，不接受路径、命令或凭据。

| 阶段 | 行为 |
| --- | --- |
| preparing | 解包和完整性核验尚未完成，普通客户端不能使用特权服务 |
| verifying | 批准记录与 launchd 配置已写入；只允许批准的 root setup 进行健康检查，普通 app / agent 被拒绝 |
| repairRequired | 安装校验、启动或健康检查失败；保留事务，停止不涉及恢复证据的本地服务，等待管理员修复 |
| 无记录 | 完整文件核验和双向身份验证的健康检查成功后，由批准的 setup 提交安装；恢复正常的 app / agent 信任规则 |

三个阶段均拒绝 VPN connect，即使是 root setup 的连接也不能启动引擎。事务存在时不允许卸载。它不会替代、删除或降级路由、DNS、PF、子进程恢复证据。

## 应用内修复

连接前检查和维护窗口显示阶段说明及“选择安装包修复…”。修复交接必须满足：事务为 root 拥有且无符号链接、目录权限完整、记录 schema 合法，并且版本/架构与当前应用一致；当前界面没有正在连接、停止、修改配置或执行维护。

用户选择可信的同架构 Local.pkg 后，应用停止自己的用户规则与登录服务，再核验事务，打开系统安装器并退出。只有这条已验证事务的交接允许绕过普通 Quit 的未知助手状态限制。安装器仍独立检查 root 恢复证据、活动程序、目录、架构和另一签名通道；不会让 GUI 声明网络已经恢复。

若系统安装器仍在运行，先等待完成。若已经中断，用同版或更新版的可信安装包重新执行管理员安装。替换前会停止不完整安装的固定 local daemon job，再次核验进程和恢复记录。只有新安装完整成功才移除屏障。取消管理员授权或再次失败时继续保留未完成状态。

记录损坏、符号链接、权限不安全、应用版本不符或存在网络恢复证据时不开放快速修复交接。不要手动删掉这些记录；仍需可信管理员诊断。此流程不承诺自动回滚历史二进制；需要回退时先完成安全维护/卸载、保留配置，再安装可信旧包。

只读支持诊断：

```sh
'/Applications/VPN Navigator.app/Contents/MacOS/VPNNavigatorApp' --vpnnav-local-installation-state
```

输出 pending、phase、repairAvailable 和说明，不修改系统、不包含配置或凭据。

## 自动化验收边界

`scripts/local-tests/test-interrupted-install.py` 仅在一次性 GitHub macOS runner 中运行。它临时构建三个故障 PKG：解包后停止、向生产 setup 提供不一致的模板触发真实失败处理、在批准/服务发布后保留 verifying 检查点。验证普通客户端被拒绝、setup 健康检查的边界、原生应用修复状态、配置哨兵保留、事务与恢复证据阻止卸载/修复，以及可信 PKG 重新完成安装。

故障脚本只在测试时替换包的私有 postinstall；产品没有故障开关。结束后恢复原始代码与候选包，故障包不会上传。检查点覆盖持久化状态，不代表已经实际模拟硬件断电、重启、系统 Installer 授权取消或完成真人点击验收；这些仍按 QA.md 在可用 Mac 上记录。结果以当前 PR 的四组安装工作流为准。
