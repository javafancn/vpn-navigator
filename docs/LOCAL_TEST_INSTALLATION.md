# 本地测试通道：安装、更新与卸载

此通道无需付费 Apple Developer ID，内置源码构建的 OpenVPN 2.7.8 / OpenSSL 3.5.9。应用和工具有本地 ad-hoc hardened-runtime 签名；PKG 没有 Developer ID Installer 签名，也未公证。它目前是供验收的候选构建，不是已通过真实网络验收的 Beta。

## 选择安装包

从本仓库通过检查的 `Local test installer and XPC trust` Actions 运行下载对应架构 artifact：Apple Silicon 使用 ARM64，Intel 使用 X64。压缩包包含：

- `VPN-Navigator-0.2.0-arm64-Local.pkg` 或 `…-x86_64-Local.pkg`：完整安装包。
- `…-Local-Uninstall.pkg`：系统组件卸载包；先在应用中完成维护准备。
- `…-Local-SHA256.txt`：两个 PKG 的完整性校验。
- `…-Local-manifest.json`：构建时生成的程序身份及文件哈希，安装后由管理员批准。

仅使用自己构建或确认来源的包。SHA-256 不是发布者身份证明。不要将来源不明的包提交给管理员授权。此通道不要求关闭 SIP，也不提供关闭 Gatekeeper 的脚本。浏览器下载后的实际系统提示和首次授权步骤仍需在用户 Mac 上验收；CI 的命令行安装成功不代表 Gatekeeper 已认可它。

## 首次安装与使用

1. 退出旧的 UI 预览实例；窗口关闭后菜单栏程序可能仍在运行。若已安装可连接版本，先完成其“升级与卸载准备”。
2. 打开同架构 `Local.pkg`，由系统安装器请求管理员授权，安装至当前系统。安装须在实际使用者的 GUI 登录会话中进行；该用户成为此本地版本的批准用户。其他用户不能调用助手。
3. 从 `/Applications/VPN Navigator.app` 启动。首次检查显示“本地安装批准”、引擎、位置、助手及配置状态。首次运行新构建会注册当前用户的每日规则更新。登录启动默认关闭，可在连接偏好中启用；不会自动连接 VPN。
4. 导入 `.ovpn`，选择 Original、全局 VPN 或中国 IPv4 直连。认证、Keychain、私钥及初始 MFA 沿用既有流程。断开后再次连接的实际服务器验收仍待记录。

应用资源内附源码归档及许可证。不要单独替换引擎、DNS hook 或助手，也不要重签名安装后的二进制；这些操作会使安装批准失效。

## 手动更新

在设置中打开“升级与卸载准备”，保持默认保留配置，点击“断开并停用后台服务”。应用检查会话、恢复网络、移除用户的规则和登录启动服务，随后通过认证 XPC 停用 root 助手并撤销当前批准。

准备成功后选择同架构、可信来源的 `Local.pkg`。应用退出，系统安装器显示版本并再次请求管理员授权。安装器在替换前拒绝活动程序、另一签名通道的助手、错误架构以及未恢复的网络记录；新程序与构建身份完全匹配后才启用服务。下一次启动重新注册规则更新；登录启动需重新开启。

每次代码变更都重新批准。正式版的在线更新仍核验同 Team ID 与系统评估结果，本地包不会进入该更新流程。跨通道迁移须先完整停用并卸载原通道，不能同时运行两个助手。

## 完整卸载

先在应用中完成维护准备，再点击“卸载本地程序…”。应用核验受保护卸载包的哈希后打开系统安装器并退出；管理员批准后移除自己的 root 服务、固定 Local 目录及仍与原批准匹配的应用。也可在退出应用后运行相应卸载 PKG。

默认保留用户配置、规则缓存和诊断。维护界面的删除复选框仅清除本应用全部配置、版本快照及 Keychain 服务项；该选择不可撤销。不删除其他应用的凭据或文件。直接拖应用到废纸篓不是完整卸载方法。系统 Installer 的安装收据可能保留，未被视为运行组件。

## 失败与修复

取消系统管理员授权不会授予新代码运行权限。维护后取消更新，服务会保持停用，可重新运行可信安装包。安装不完整、权限异常、哈希变化会阻止 XPC 或特权引擎启动；不会自动切换到较弱信任方式，也不会自动批准现存未知文件。

先使用应用的断开及网络恢复功能；仍有路由、DNS、PF 或子进程记录时不允许升级或卸载，不要手动删除记录。安装事务失败不承诺自动回滚：应保留原可信安装包，待会话安全停止后重装；原包恢复需要再次管理员批准。若助手身份损坏导致无法完成恢复或停用，暂需人工诊断，不能在 UI 中强行绕过。这是候选版待补齐的故障处理范围。

## 从源码构建

在原生架构 macOS 上，按 `INSTALL_AND_RELEASE.md` 拉取并构建锁定源码，设置源码路径/哈希及 notices 后：

```sh
export OPENVPN_BIN=/absolute/engine-prefix/sbin/openvpn
export THIRD_PARTY_NOTICES=/absolute/engine-prefix/share/vpn-navigator/THIRD_PARTY_NOTICES.txt
VPNNAV_CHANNEL=local-test zsh scripts/build-app.sh
zsh scripts/build-local-pkg.sh
```

源码下载脚本在 Actions 中自动设置 `GITHUB_ENV`；本地终端需自行从其 `sources.json` 导出相应变量。无付费证书不会影响此构建。本地包每个架构单独构建和验收。

## 验收边界

自动检查覆盖原生代码编译、模型及现有连接测试、实际 PKG 安装、合法/冒充双方的 XPC 校验、引擎权限及内容变更、用户服务、维护撤销、恢复证据阻止更新/卸载、重新安装和完整系统卸载。结果以具体 Actions 运行记录为准。

真实 TLS/MFA 服务器、物理 DNS/出口与 IPv4/IPv6 抓包、网络切换/睡眠/重启、助手崩溃恢复、长时运行、管理员取消及浏览器下载后的 Gatekeeper 流程仍需人工 Mac 验收。macOS 13 为声明的最低构建目标，不表示已通过 13 真机安装测试。不得据此宣称已达到正式发布或防泄漏验收标准。
