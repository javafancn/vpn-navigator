# 0.8.17 / Build 37：功能与性能检查

本轮检查以 0.8.16 为基线，覆盖状态轮询、安装信任校验、规则处理、模式切换、路由日志与异常恢复。已修复以下三项，不代表完整实网验收通过。本机已安装程序未被替换。

## 1. 本地版高频轮询重复校验整套程序

`HelperClient.installationStatus`、客户端 XPC 身份要求和助手的调用者校验都会调用 `LocalInstallation.load()`。此前每次均执行完整签名检查和 SHA-256，重复读取约 17 MB 的已安装本地程序。状态轮询约每秒触发，部分调用在主线程。

只读测量：旧实现一次完整校验的热运行约 27–32 ms，首次约 175 ms。新实现首次仍执行完整校验；文件未变时重复调用约 0.05–0.09 ms。另一轮首次为 142 ms，显式强制完整校验为 67 ms。数据仅代表同一本机的单次校验路径，不是 VPN 吞吐或整体 UI 能耗测量。

实现采用进程内、带锁的单条缓存。每次使用仍对全部固定输入路径执行 `lstat`，比较 inode/device、大小、所有者、组、权限、硬链接数以及纳秒级修改/变更/创建时间；审批记录、退役记录、安装事务和父目录也在范围内。任何变化、读取错误或校验失败都会使缓存失效；验证过程中发生变化也拒绝使用结果。没有时间窗内无条件信任或跨进程持久化缓存。

引擎启动、助手启动、安装完成和维护退役显式执行完整验证；XPC 的 OS 代码身份要求及调用者身份检查保留。Developer ID 通道没有使用此本地审批缓存。

## 2. 反复模式切换会使日志超过恢复容量

旧日志只追加路由 begun/committed 事件。用 4096 条路由生成 5 次完整往返，日志为 **16,097,280 字节**。重放显示操作完整、没有剩余路由，但恢复入口因 16 MB 上限而拒绝读取。长期会话或助手异常后可能因此无法自动恢复。

新实现每增长约 4 MB，在下一次完整事务之间，用原子、落盘的检查点替换已提交历史。检查点保存当前 IPv4/IPv6 所有权及其顺序，后续每条路由操作仍写 begun、执行内核操作、写 committed，并分别同步落盘。新旧 inode 之间的追加句柄会切换，避免日志写入已替换的旧文件。

检查点只允许作为日志第一条记录；未知版本、重复路由、流中间的检查点均拒绝自动恢复。不完整或失败的事务不会被压缩。检查点须小于 12 MB，为后续事件留下容量；测试构造的 60,000 条双栈路由检查点为 5,815,704 字节。

已有的旧版超限日志不会被直接删除或绕过容量/所有权检查，需保留证据单独诊断；本次防止新会话持续积累至该状态。

## 3. 没有末尾换行的旧日志在中断恢复后可能损坏

旧版 JSON 数组日志可没有末尾换行。直接追加下一条 JSON 事件会把数组和事件连为一行；若恢复中途失败，留下的日志无法正常解析。

对已完整、可确认的此类日志，恢复前先生成原子检查点，再继续追加。测试同时覆盖正常清理完成和第二条删除失败：失败记录保持可解析且仍是不确定事务，不自动清除证据。
