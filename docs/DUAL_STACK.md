# IPv6 与双栈支持

0.5.0 / Build 14 将 IPv6 接入实际受管路由。原始配置模式继续由 OpenVPN 配置控制；全局、规则模式由助手统一安装 IPv4／IPv6 路由。

## 连接与保护

- 支持通过 IPv4 或 IPv6 服务器地址建立 OpenVPN 连接。服务器地址、端口和已选择的传输族会在保护重连期间保持固定；不支持带接口作用域的链路本地服务器地址。
- 根据服务器实际分配的 IPv4、IPv6 隧道地址安装对应地址族的默认路由，显示助手确认的 IPv4、IPv6 或双栈状态。IPv6 不需要另一个 VPN 会话。
- 设置中可要求受管连接必须建立双栈，缺少任一地址族时拒绝连接。默认自动协商；不支持某个地址族时仍须满足保护条件，不会把缺少 IPv6 的连接标为双栈。
- IPv4-only 服务器遇到可绕行的 IPv6 默认出口时，需要启用保护，或更换双栈服务器；IPv6-only 隧道在受管模式下需要保护以阻断未承载的 IPv4。原始模式不由应用保证这些路径。
- 实验性 PF 保护只放行本次隧道、固定服务器端点、明确的直连范围及必要的 DHCP／IPv6 邻居发现。IPv6 默认阻断规则仍保留，隧道和直连放行位于其前；没有使用“放行所有物理 IPv6”的规则。
- 没有 PF 的连接仍依赖路由与定期核验，不提供无泄漏保证。物理出口或本地网段改变时停止受管连接并走既有恢复流程。

## 双栈分流

全局模式将服务器承载的默认 IPv4／IPv6 流量送入隧道。规则模式分别使用中国 IPv4 前缀和 APNIC 的中国 IPv6 注册前缀，后者反映注册归属，并不等于精确地理位置。

路由工作区可更新两类规则，IPv6 卡片也支持单独更新；每日规则代理会获取和校验两类数据。接收数据的助手重新执行格式、数量和变化幅度验证。活动规则会话的两类路由及 PF 在同一事务中更新；遇到不能确定的系统写入结果时停止连接、保留恢复记录。缓存文件是用户侧数据，写入失败时以助手的实际会话与路由核验结果为准，不回退已验证的网络策略来掩盖存储错误。

自定义规则仍按配置保存，总数最多 128 条。支持 IPv4 /8–/32、IPv6 全球单播 /16–/128 和 ULA /7–/128，单个地址自动转为主机前缀。启用规则在同一地址族内不能重叠；端点与当前物理局域网受保护。IPv6 走 VPN 的例外会从 IPv6 物理路由和 PF 直连范围中同时扣除。服务器未承载该地址族时拒绝应用其自定义规则，避免无声忽略。

## DNS、解释与排障

继续使用受信任的 OpenVPN DNS hook，支持包含 IPv4／IPv6 服务器地址的系统解析器设置；恢复日志保留所有权比较。没有 IPv4 主网络服务时可使用 IPv6 主服务。并未新增独立 DNS 代理、DoH 或域名分流。

路由解释、TCP 探测、路由追踪和一键排障均可输入 IPv4／IPv6。域名查询显示系统返回的两类地址。实际核验仍绑定配置、连接尝试和路由版本，读取正确地址族的系统接口与网关；不发出路由查询目标的数据包。IPv6 被保护策略阻断时，系统路由表仍可能显示物理接口，界面会区分“存在路由”和“允许流量”。

只读路由采样不证明服务器可访问公网或没有 DNS／IPv6 泄漏；目标 TCP 失败也不直接判定整个 VPN 故障。排障不会自动修改系统 DNS、重启 VPN 或删除恢复证据。

便携 .ovpn 导出保留原始自包含配置，不写入应用策略。静态路由预览中的 IPv6 策略以注释说明；实际物理 IPv6 网关需在连接时核验，不能在离线导出中猜测。

## 恢复与验证

IPv4 和 IPv6 写入同一份 root 所有的 routes.journal，均采用写前记录与提交记录。任何地址族存在未确认写入都会阻止自动恢复；只有在原 OpenVPN 子进程已退出、路由所有权可核验时才撤销。旧 IPv4 日志可继续读取，安装、升级、卸载和退出的恢复屏障无需另一套旁路记录。

核心与注入测试覆盖双栈地址、IPv6 区间扣除、规则优先级、两种服务器地址族、混合日志、在线模式往返、PF 收紧顺序和错误恢复。CI 安装测试覆盖真实 IPv6 TLS 传输、双栈及 IPv6-only 隧道地址、IPv6 隧道回显、固定文档网段的实际内核路由安装与撤销。内核测试入口仅编入 Local Test 通道，要求 root、CI 标记和已批准的助手身份，使用既有测试 utun，不改变默认路由。

公网服务器的双栈转发、IPv6 物理出口、ND／DHCPv6、DNS 分域、多网卡切换、休眠恢复、断线保护抓包与长时间运行仍需物理环境验收。本次不发布 Beta 或 Release。
